# LaserLab v0.9.8 — proposed release notes

**Draft only.** Do not announce availability until final qualification and publication. v0.9.7 remains the published release.

## What is new

- System Check and CLI diagnostics distinguish optional English Tesseract from the seven CodeOfReality reference-glyph templates.
- Template OCR attempts no longer inherit misleading English language or script metadata.
- Standalone font OCR reports whether the comparison completed; valid abstention is a successful execution, while unavailable or failed engines return a nonzero exit code.
- Synthetic calibration distinguishes genuine negative-control rejections from false matches and execution failures.
- Native package checks exercise the compiled font OCR command against synthetic blank and geometric images, independently of Tesseract.
- Native archive qualification checks version, revision, checksum and bundled font identity on Windows, Linux, Intel macOS and Apple Silicon.

No change to the recognition thresholds or primary scientific scoring. Synthetic checks are not evidence of empirical recognition accuracy or decoded laser text.

## Release gate

1. Merge reviewed, passing PRs #104 and #105, and any release-staging changes.
2. In Actions, run Cross-platform Release on the exact intended main revision with publish disabled (or use its completed automatic main candidate run). Record the full commit SHA and run ID.
3. Confirm both Python suites, all four native packages, and the field-test checklist. Record independent machine acceptance separately from automated CI. Do not claim an unreproduced community report is resolved.
4. Only when ready, manually run **Stage LaserLab v0.9.8 draft** on main using that candidate run ID and full SHA. The workflow refuses mismatched revisions, missing qualification jobs or an existing version tag. It creates an immutable tag and dispatches tagged qualification with publish=false.
5. Inspect the resulting draft, four archives and SHA-256 sidecars. Review release notes, outstanding field acceptance, and package evidence. Publication is a separate maintainer decision; this workflow never publishes automatically.

If tagging succeeds but the release dispatch fails, do not move or recreate the tag. Inspect the existing tag and manually run Cross-platform Release on it with publish disabled.

The original community report #96 and independent validation remain open until supported by actual evidence.
