# LaserLab 0.9.8 — candidate validation plan (not an official release)

**Status:** development-only. The latest officially published native release
remains **v0.9.7**. Do not distribute a development build as v0.9.8 final,
claim field acceptance, or tag/publish the release until reviewed native builds
and user reports warrant it.

## Candidate changes since v0.9.7

- Distinguish optional Tesseract's usual English `eng` OCR from opt-in
  CodeOfReality reference-glyph templates in **Help > System Check**,
  readable CLI diagnostics, and saved-candidate Review.
- Report selected glyph variants and the readiness of all seven reference
  fonts, with explicit disabled/invalid selections and per-variant unavailable
  states; don't silently substitute Tesseract.
- Warn users who opt into the matcher when references cannot be verified.
- Native candidate smoke now selects all seven template variants and verifies
  the packaged CLI diagnostic report, requiring every reference to be verified.
  This is separate from packaging the seven font bytes and from Tesseract
  availability. It does **not** measure recognition accuracy.

## Native qualification before release

1. Build candidate archives on Windows x86-64, Linux x86-64, macOS x86-64
   and macOS arm64 via **Cross-platform Release** on the exact reviewed commit,
   without publication. Packaging- and OCR-related pull requests trigger the four-platform
   candidate matrix; these builds identify the PR merge revision, not the final
   merged commit. Relevant pushes to main also trigger the matrix for the exact
   merged revision. Superseded candidate runs on the same ref may be cancelled.
   Before tagging, verify successful qualification for the exact intended commit;
   manually dispatch a candidate if its revision has no completed run.
   Record each archive's SHA-256 and `BUILD-INFO.json`
   `source_revision`, `build_channel=candidate` and `version=0.9.8`.
2. Confirm both Python CI suites (3.10, 3.11), GUI, CLI, fixtures, packaged
   font verification and synthetic benchmark smoke pass. Treat automated X11
   startup as a smoke check, not a human usability result.
3. On a physical machine, launch the extracted GUI, check **Help > System
   Check**, enable experimental CodeOfReality comparisons and run one *synthetic,
   high-contrast isolated glyph* through the matching path. In Review, record
   which engines actually ran and preserve missing/no-match/abstaining outcomes.
4. Repeat with the matcher disabled to confirm English Tesseract output does
   not imply the CodeOfReality engine ran. Test upgrade from older versions
   without deleting any personal experiment directory.
5. For [field report #96](https://github.com/ProhibitedTV/LaserAnalysisAI/issues/96),
   request the original reporter's OS, exact executable/build identity, clicks
   or command, and the output that said English rather than a template match.
   Request only a user-reviewed redacted support bundle if necessary, not
   original laser recordings or participant data.

Follow [release qualification](../release_qualification.md) and
[the first-user checklist](https://github.com/ProhibitedTV/LaserAnalysisAI/wiki/First-User-Check).
No synthetic font/self-consistency result proves decoding of a language,
a DMT-related mechanism, or any message in laser footage.
